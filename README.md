# WINSERV

A self-contained Windows tray application that gives students a working
PHP + MariaDB (+ Node) web development stack on lab machines, with no
administrator rights and no separate installers. Built for FE classroom use
where machines may be re-imaged between terms and students cannot install
software or edit system PATH themselves.

Double-click `WINSERV.exe`, run the one-time setup wizard, click **Start
All**, and `http://localhost:8080` is a working PHP site backed by a local
MariaDB database — entirely inside the student's own file area, with
nothing written to Program Files or the registry.

## Features

- **System tray app** — runs quietly in the tray; the control panel shows
  live status and log output for both services.
- **PHP** — runs via PHP's built-in web server (`php.exe -S`), pointed at a
  configurable `WebRoot` folder.
- **MariaDB** — runs as a plain child process (not a Windows Service), so no
  admin rights are needed to start/stop it. First run initialises the data
  directory and sets the root password automatically.
- **Node.js** — bundled as portable tooling. Not started by WINSERV; a
  generated `.vscode/settings.json` puts `node`/`npm`/`npx` on the VS Code
  integrated terminal's `PATH` for the current `WebRoot` only.
- **Adminer permalink** — `http://localhost:<port>/adminer/adminer.php`
  always reaches a database admin UI, regardless of which project `WebRoot`
  currently points at, via a small PHP router script (see below).
- **Setup wizard & Settings dialog** — choose install path, ports, and the
  MariaDB root password; change them later without reinstalling.
- **Daily rotating log file** of all service output, for after-the-fact
  troubleshooting.

## Requirements

- **To build:** .NET 8 SDK (Windows).
- **To run:** nothing — the published `WINSERV.exe` is self-contained and
  bundles the .NET 8 runtime. See [BUILD.md](BUILD.md) for build and
  deployment instructions, including how to assemble the companion
  `WINSERV-runtime.zip` (portable PHP + MariaDB + Node, and optionally
  Adminer).

## Quick Start

1. Build or download `WINSERV.exe` and `WINSERV-runtime.zip`, placed in the
   same folder (see [BUILD.md](BUILD.md)).
2. Run `WINSERV.exe`. The setup wizard appears on first run.
3. Choose an install path (default `C:\WINSRV`) and click **Install**.
4. In the control panel, click **Start All**.
5. Visit `http://localhost:8080` (or your configured port).

## Project Layout

| File | Purpose |
|---|---|
| `Program.cs` | Entry point, single-instance guard, global exception handling |
| `TrayApplicationContext.cs` | Owns the tray icon and application lifetime |
| `MainForm.cs` / `.Designer.cs` | The control panel window |
| `SetupWizard.cs` / `.Designer.cs` | First-run install wizard |
| `SettingsForm.cs` / `.Designer.cs` | Settings dialog |
| `ServiceManager.cs` | Coordinates starting/stopping PHP and MariaDB |
| `ProcessWrapper.cs` | Abstract base for managing a child process |
| `PhpServer.cs` | PHP built-in server + router script + `php.ini` generation |
| `MariaDbServer.cs` | MariaDB process management + first-run initialisation |
| `RuntimeInstaller.cs` | Extracts `WINSERV-runtime.zip`; deploys Adminer |
| `AppConfig.cs` / `ConfigManager.cs` | `config.json` model and persistence |
| `DiskLogger.cs` | Daily rotating log file |

## Configuration

Settings live in `config.json`, next to `WINSERV.exe`. Edit it directly or
use the Settings dialog in the app. See [BUILD.md](BUILD.md) for the full
field reference, default ports, and troubleshooting table.

## Adminer

A router script (`{InstallPath}\tools\router.php`, regenerated by WINSERV on
every PHP start) intercepts `/adminer*` requests so the permalink works no
matter which project is the current `WebRoot`. Adminer itself is vendored
separately (not embedded in WINSERV's source) — see the **Adminer Permalink**
section of [BUILD.md](BUILD.md) for how to add it to the deployment package
or deploy it later from the Settings dialog.
